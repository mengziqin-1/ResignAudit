# 面向离职风险的电子数据取证与证据链审计系统

本项目是“电子数据取证系统研发”实训项目，面向企业员工离职场景下的数据外传风险，设计并实现一个本地运行的电子数据取证辅助分析系统。

系统当前采用“本地 Web 审计台 + Flask 本地分析服务 + Python 分析模块”的架构：用户通过浏览器打开审计台，填写员工姓名和取证数据目录，后台在本机完成文件扫描、聊天样本分析、浏览器记录分析、USB 使用痕迹分析、风险评分、证据链归并和报告生成。

> 注意：本项目是课堂实训中的轻量级取证辅助系统，不等同于企业级远程全量自动取证平台，也不能替代专业取证软件。它更适合用于授权场景下的本机样本分析、风险研判演示和报告生成。

## 当前版本重点

- Web HTML 是主要操作入口，`api.py` 启动本机 Flask 服务提供分析接口。
- 系统不再只是简单关键词检索，而是加入“关键词权重 + 规则评分 + 证据类型 + 证据链完整度”的分析结构。
- 首页重做为“离职风险证据链审计台”，默认突出证据链、评分解释和证据强度。
- 支持生成 HTML/PDF 报告，报告中包含风险评分、证据类型说明、证据链分析、时间线和审计发现。
- 增加本地访问 token，避免接口被随意调用。
- 支持复制路径和安全打开所在文件夹，提升本地取证查看效率。

## 系统定位

本系统解决的是“取证材料已经在本机或样本目录中，如何进行集中分析和风险解释”的问题。

它可以做：

- 扫描指定工作目录中的文件、压缩包和文档内容。
- 分析标准化聊天数据库样本。
- 尝试读取本机 Chrome、Edge、Firefox 浏览器历史记录。
- 尝试读取 Windows 注册表中的 USB 设备使用痕迹。
- 根据规则引擎计算风险分数。
- 将文件、内容、聊天、浏览器、USB 记录统一归并为证据事件。
- 生成“敏感资产 -> 打包聚合 -> 外传意图 -> 外传通道 -> 外设条件”的证据链。
- 输出 HTML/PDF 审计报告。

它暂时不能完整做到：

- 远程自动采集员工电脑数据。
- 破解或解密真实微信、企业微信、钉钉等加密数据库。
- 还原已删除文件、已删除聊天记录、完整磁盘镜像。
- 证明 USB 一定发生了文件复制，除非有真实文件操作日志。
- 多用户登录、企业权限管理、多客户端任务下发、案件中心、审计审批流。

## 两个“端”的理解

项目里容易把“客户端”和“Web 端”讲混，这里建议这样理解：

| 端 | 当前实现程度 | 作用 |
| --- | --- | --- |
| 本地采集/分析端 | 约 70% | 由 Python 模块和 Flask 后台完成本机扫描、样本分析、评分、证据链和报告生成。 |
| Web 审计台/管理端 | 约 30% | 负责参数输入、进度展示、结果查看、证据链展示和报告下载，目前还不是完整企业管理平台。 |

当前项目更准确的定位是：**本地电子取证分析辅助工具 + Web 可视化审计台**。

## 技术架构

```text
浏览器 HTML 审计台
        |
        | HTTP 请求，本机 token 校验
        v
Flask 本地服务 api.py
        |
        v
AuditOrchestrator 审计编排器
        |
        +-- FileScanner 文件扫描与压缩包检查
        +-- ContentAnalyzer 文档内容分析
        +-- ChatAuditor 聊天样本分析
        +-- BrowserAnalyzer 浏览器记录分析
        +-- USBAuditor USB 使用痕迹分析
        +-- RuleEngine 渐进式风险评分
        +-- EvidenceEngine 证据事件与证据链归并
        +-- TimelineAggregator 时间线聚合
        +-- HTML/PDF Report 报告生成
```

核心模块说明：

| 文件 | 作用 |
| --- | --- |
| `api.py` | Flask 本地 Web 服务，提供启动审计、查询进度、下载报告、打开所在文件夹等接口。 |
| `templates/index.html` | Web 审计台首页，展示证据链、评分解释、时间线和审计发现。 |
| `src/modules/audit_orchestrator.py` | 审计总编排器，把所有模块串成完整流程。 |
| `src/modules/keyword_policy.py` | 关键词分级和权重策略。 |
| `src/modules/evidence_engine.py` | 标准化证据事件，构建五段式证据链。 |
| `src/modules/rule_engine.py` | 渐进式风险评分规则。 |
| `src/modules/html_report.py` | 生成 HTML 报告。 |
| `src/modules/pdf_report.py` | 生成 PDF 报告。 |
| `main.py` | 早期 PyQt 本地客户端入口，当前保留为桌面端参考实现。 |

## 核心分析逻辑

### 1. 关键词分级

系统不再把所有关键词都看成同一等级，而是按证据含义分为：

- 高危资产词：如客户名单、源代码、合同、财务数据。
- 外传行为词：如发送、上传、打包、复制、带走。
- 外传通道词：如网盘、云盘、个人邮箱。
- 普通弱线索：如项目、方案、流程等。

不同类别具有不同权重，并在报告中体现“证据强度”。

### 2. 渐进式评分

评分不采用简单“命中即高危”的二值判断，而是根据数量、权重和组合情况累积分数。

主要规则包括：

- 敏感内容命中。
- 非工作时间密集文件操作。
- USB 设备使用痕迹。
- 聊天记录中的外传相关表达。
- 网盘/邮箱访问。
- 大量文件打包。
- 多源证据组合风险。

风险等级：

| 分数 | 等级 |
| --- | --- |
| `>= 60` | 高风险 |
| `30 - 59` | 中风险 |
| `1 - 29` | 低风险 |
| `0` | 无风险 |

### 3. 证据链分析

系统会尝试把不同来源的数据组织成五段式链路：

```text
敏感资产 -> 打包聚合 -> 外传意图 -> 外传通道 -> 外设条件
```

这条链不是直接宣判员工泄密，而是帮助审计人员判断：当前取证材料是否已经形成较完整的外传风险链路。

## 快速运行

### 方式一：一键启动 Web 审计台

Windows 下双击：

```text
launch-web.cmd
```

启动后访问：

```text
http://127.0.0.1:5000
```

推荐演示输入：

```text
员工姓名：张三
取证数据目录：test_data
聊天数据库样本：可留空，系统会尝试自动识别
```

### 方式二：命令行启动

安装依赖：

```bash
pip install -r requirements.txt
```

启动 Web 服务：

```bash
python api.py
```

访问：

```text
http://127.0.0.1:5000
```

### 方式三：PyQt 桌面端

项目保留早期桌面端入口：

```bash
python main.py
```

当前课堂展示更推荐使用 Web 审计台，因为它更能体现证据链、评分解释和报告可视化。

## 测试数据

`test_data` 目录用于课堂演示：

- `mock_chat.sqlite`：标准化聊天记录样本。
- `客户资料打包.zip`：模拟离职前打包敏感资料的压缩包。
- 其他样本文档：用于验证关键词识别、压缩包检查和时间线聚合。

## 报告输出

系统运行后会在 `reports/` 目录生成报告，通常包括：

- PDF 审计报告。
- HTML 审计报告。

报告内容包括：

- 基本审计信息。
- 风险评分与风险等级。
- 证据类型说明。
- 证据链分析。
- 审计发现。
- 事件时间线。
- 证据清单。

## 安全与边界

- Web 服务默认只监听 `127.0.0.1`，用于本机访问。
- 接口使用本地 token 校验，减少误调用风险。
- 浏览器页面本身不能直接扫描任意本地目录，真正扫描由本机 Flask 后台完成。
- “USB 使用痕迹”不直接等于“文件复制”，除非存在明确文件操作日志。
- 本系统用于授权取证和课堂实训，不建议用于未经授权的数据扫描。
